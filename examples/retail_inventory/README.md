# Retail: inventory forecasting and reorder agent

An agent that forecasts demand per SKU and turns it into a purchase plan:
what to reorder, how much, from which supplier, and what it will cost.

## Run

```bash
python -m examples.retail_inventory.run                      # offline mock provider
python -m examples.retail_inventory.run --provider openai -v
python -m examples.retail_inventory.run --provider anthropic \
  --task "Plan orders at a 98% service level with a 14-day review period."
```

Options shared by all examples: `--provider`, `--model`, `--task`, `--data-dir`,
`--max-steps`, `--trace-file trace.jsonl`, `-v` (log every model and tool call).

## Tools

| Tool | What it does |
|---|---|
| `list_products` | SKUs with stock on hand, on order, supplier and lead time |
| `get_sales_history` | Daily units sold for one SKU over the last N days |
| `forecast_demand` | Daily demand forecast with a simple moving average (`sma`) or simple exponential smoothing (`ses`), plus forecast error |
| `compute_reorder` | Safety stock, reorder point, order-up-to level and order quantity for one SKU |
| `reorder_report` | The reorder policy for every SKU, most urgent first, with total order cost |

### Reorder policy

With forecast daily demand `d`, its error `σd`, lead time `LT` (std-dev `σLT`),
review period `R` and service-level factor `z`:

```
safety stock   SS  = z * sqrt(LT * σd² + d² * σLT²)
reorder point  ROP = d * LT + SS
order-up-to    S   = d * (LT + R) + SS
```

If inventory position (on hand + on order) is at or below `ROP`, the agent
orders `S - position`, at least the supplier's minimum order quantity and
rounded up to whole packs. A SKU is **critical** when on-hand stock will run
out before a new order could arrive (days of cover < lead time).

## Data (synthetic)

All files in `data/` are **synthetic** and generated by
`data/generate_data.py` (seeded, reproducible). Products and suppliers are
fictional.

| File | Columns |
|---|---|
| `sales_history.csv` | `date, sku, units_sold` (120 days, 8 SKUs) |
| `stock.csv` | `sku, name, on_hand, on_order, unit_cost` |
| `lead_times.csv` | `sku, supplier, lead_time_days, lead_time_std_days, min_order_qty, pack_size` |

Use your own data by pointing `--data-dir` at a folder with the same three files.

## Files

- `tools.py` - analytics and the tool registry
- `prompts.py` - system prompt, default task and the scripted mock run
- `run.py` - CLI entry point
- `tests/` - offline tests for the tools and the agent loop

## Limitations

The forecasts are deliberately simple (no seasonality, promotions or
stockout-censored demand). Swap in your own forecasting in `forecast()`; the
agent and tools do not need to change.
