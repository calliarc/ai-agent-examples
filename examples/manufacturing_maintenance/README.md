# Manufacturing: maintenance-log analyzer

An agent that reads a raw maintenance log, groups recurring failures by
machine and component, computes MTBF/MTTR, and flags machines at risk of
failing again, with suggested next actions.

## Run

```bash
python -m examples.manufacturing_maintenance.run                    # offline mock provider
python -m examples.manufacturing_maintenance.run --provider anthropic -v
python -m examples.manufacturing_maintenance.run --provider openai \
  --task "Assume two 8-hour shifts. What is PRESS-02's MTBF and what keeps failing?"
```

## Tools

| Tool | What it does |
|---|---|
| `parse_logs` | Parse the log: record counts, window, failures by machine/component, skipped lines |
| `list_events` | Individual events filtered by machine, event type and component |
| `find_recurring_failures` | Group failures by machine + component (or fleet-wide by component) |
| `compute_mtbf` | MTBF, MTTR and availability per machine |
| `flag_at_risk_machines` | 0-100 risk score per machine with the reasons behind it |

### Parsing

Each line is `timestamp | machine | event | description | downtime=… | tech=…`.
Event types are case-insensitive (`failure`, `preventive`, `inspection`),
downtime accepts `95m`, `1.5h`, `2 hours` or plain minutes, and blank or `#`
lines are ignored. Malformed lines are reported, not silently dropped. The
component is inferred from the free-text description with a keyword taxonomy
(`COMPONENT_KEYWORDS` in `tools.py`), so "hyd. pump cavitation" and
"Hydraulic pressure drop" both count as `hydraulic`.

### Metrics

```
operating hours = window days * hours_per_day - failure downtime
MTBF            = operating hours / failures
MTTR            = mean failure downtime
availability    = MTBF / (MTBF + MTTR)
```

Risk score (capped at 100): up to 35 for MTBF worse than the fleet median, up
to 25 for a component failing repeatedly, 20 if the failure rate in the last
`recent_days` is rising versus earlier history, and up to 20 when the time
since the last failure is approaching or past the machine's MTBF. Machines at
or above `threshold` (default 50) are flagged.

## Data (synthetic)

`data/maintenance_log.txt` (about 220 events, Jan-Aug 2026) and
`data/machines.csv` are **synthetic**, generated by `data/generate_data.py`.
Machines and technicians are fictional. The log includes a deliberately
malformed line, mixed casing and mixed downtime units. Point `--data-dir` at a
folder with your own `maintenance_log.txt` (and optionally `machines.csv`).

## Files

- `tools.py` - parser, analytics and the tool registry
- `prompts.py` - system prompt, default task and the scripted mock run
- `run.py` - CLI entry point
- `tests/` - offline tests for the parser, metrics and the agent loop
